Blender Agent · 新版 UI 需求与交互原型

这份文件是交接物：给设计方（人或 AI）做新版界面设计用。里面 ① 锁死了 Blender 5.2 真实能用什么控件 ② 列了全部界面状态（可点） ③ 逐条需求带控件级实现约束和验收标准 ④ 交付格式要求。右侧沙盒里的每个小面板都是"用 Blender 真做得出来的样子"画的，不是网页效果图。
最重要的一条硬约束：Blender 面板没有颜色系统、没有字体控制、没有 CSS 动画。可表达的状态色只有两种——layout.alert = True（红）与 active/enabled（灰）。图标只能用内置枚举（5.2 共 1033 个，名字写错会让整块面板从那一行起静默截断，这是我们踩过的真实事故）。任何"渐变卡片、圆角气泡、悬浮层、淡入动画、品牌色"的方案都无法实现，请直接不要提。

  • 纯文本 tooltip 任何属性的 description=

✗ 不可用（已实测不存在，别再设计上去）

  • StringProperty(subtype='MULTILINE') —— 合法 subtype 只有 FILE_PATH / DIR_PATH / FILE_NAME / BYTE_STRING / PASSWORD / NONE
  • UILayout.menu_enum、operator_search、toolbar_item、constraint
  • Panel.bl_options 里没有 SCROLLABLE 之类的枚举；Panel 属性表里没有任何滚动开关
  • 任意 RGB 颜色 / 字体 / 字号 / 行高 / 圆角 / 阴影 / 透明度 / 动画时长 —— 只有 alert 与 scale_*
  • 图标名黑名单（实测不存在）：PREFS（正确是 PREFERENCES）、DOC、NETWORK、TOKEN
  • 图标名白名单（实测存在，可直接点名用）：CHECKMARK · ERROR · TIME · INFO · TEXT · CONSOLE · PLAY · CANCEL · X · PREFERENCES · SETTINGS · OPTIONS · FILE_TICK · ADD · REMOVE · TRASH · ARROW_LEFTRIGHT · EYEDROPPER · DUPLICATE · LINKED · UNLINKED · HELP · URL · FUND · PLUGIN · PROJECT · MENU_PANEL · GRIP · RADIOBUT_ON/OFF · CHECKBOX_HLT · TRIA_DOWN/RIGHT/UP/LEFT · DISCLOSURE_TRI_DOWN · STATUS_INFO · STATUS_WARNING · STATUS_ERROR · RECOVER_LAST · FILE_SCRIPT · ASSET_MANAGER

? 需要 GUI 实测后才能定（别猜）

  • 侧栏内容超高时到底能不能滚：RNA 里没有 scrollable，但界面实测可能整块 UI 区可滚。这直接决定"转录区最多放多少行"。测法：注册一个画 200 行 label 的 Panel，开 GUI 看。
  • textbox 里 Enter / Shift+Enter 的实际行为（提交？换行？）—— 决定"执行"按钮要不要保留。
  • label 文本被从中间裁断的确切触发宽度（同行项目实测存在此现象，故长文本必须自己折行）。
  • template_list 的行高、能否显示多行折行内容、有没有滚动条。
  • 本机环境约束：无头渲染全黑（EEVEE 无 GL 上下文）、render.opengl 无头直接报错 → 任何"截图回传给模型"的功能只能在有 GUI 时用，必须设计降级。
  • 本机走系统代理 127.0.0.1:7890；代理没开时报的是 502 而不是连接失败 → 错误态文案必须覆盖这一类。

◉ 产品前提（不是界面，但会影响设计）

  • 模型：deepseek-flash（deepseek-v4-flash 已被官方标记弃用）；模型名在偏好设置里可改。
  • 实测一条指令：4 轮 / 3.9 秒 / 输入 1576 token（缓存命中 1408）/ 输出 61 token ≈ ¥0.0004。→ 不要为省 token 牺牲多轮历史，钱不是约束。
  • 当前只有 5 个工具：get_scene_info / create_primitive / set_material / transform_object / execute_blender_code。
  • 网络请求同步阻塞主线程（MVP 决定）。所以"停止"只能停在轮与轮之间，中断不了正在飞的那一次 HTTP 读——界面文案必须诚实，不能画一个像"立即取消"的按钮。
  • Key 存在 Blender 偏好设置里，明文；PASSWORD 子类型只是显示打码。

④ 给设计方的要求

必须做到

  • 输出控件级方案：每个元素点名用哪个 Blender API（textbox / progress / template_list / operator + 具体图标名…）。只给视觉效果图视为未完成。
  • 图标只能从上面白名单里选，且必须写出名字。
  • 同时给默认宽 / 加宽 / 极窄三档（顶部按钮可切，注意 word-break 后中文不溢出）。
  • 每个状态给完整中文文案（含错误态下一步动作），不要留 Lorem 或"待定"。
  • 长文本必须设计折行方案（Blender 会把过长 label 从中间裁断）。
  • 状态优先级：忙态与错误态 是这次重做的核心目标，不能只美化空闲态。

不要做

  • 不要 hover 效果、不要 CSS 动画/过渡、不要自定义字体或颜色、不要圆角阴影渐变。
  • 不要假设能滚动面板（见"未验证"清单），除非你把"实测方法"一起写进去。
  • 不要设计"立即取消正在发送的请求"这类做不到的交互。
  • 不要引入登录/账号/云同步（用户明确拒绝鉴权类设计）。
  • 不要把对话挪到外部客户端 —— 本项目就是要在 Blender 里做完。
  • 不要新增需要 pip 安装的第三方依赖（Blender 内嵌 Python 里装不了 openai，这是实测结论）。

必须回答的问题

  • 28 个状态里，哪些能合并进同一屏而不靠折叠隐藏？（折叠=看不见=等于没有）
  • 多轮历史堆到 20 条时，这一屏怎么排？给三种方案。
  • "可撤销回执"放在哪一层，才能让人在提交后 1 秒内看到它改了什么？
  • 视口截图缩略图（template_icon）值不值得占这一格？它只在有 GUI 时可用。
  • 错误态怎么在不使用颜色的前提下区分"我能自己重试"和"你得去改设置"？
