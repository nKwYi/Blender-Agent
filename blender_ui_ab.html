纠正上一版

上一版原型不是你的现有 UI

它是按可用 API 重画的一版新设计，不是在你现在这套界面上做的调整。所以你打开 Blender 对不上，是对的。 左边全部是真实截图，右边是方案。

先说清楚一件事：上一版页脚写的「1:1 复刻」说过头了。复刻的只有配色值（那部分确实是从你本机主题实时读的）， 控件高度、行高、内边距、侧栏宽度全是我估的。右边看着比左边"高级"，有一部分只是因为我画得比实际宽松。

对话展开态

这一张差别最大，因为结构完全不同。

现状一整块嵌套深色块 ui.py:963-1030

cbox = layout.box() 建一个大盒，用户消息、AI 消息、步骤清单全部再往里嵌一层 （cbox.box() → abox.box()）。所以视觉上是一整块几乎无分隔的深色区域， 消息之间只能靠缩进和图标区分。

建议每轮消息独立成块 平铺 + 原生子面板

不套那个大 cbox，每轮消息各自一个平级 box， 「执行建模操作」用 layout.panel() 原生折叠。 结构一变，消息之间的分界靠底色和间距就出来了，不需要靠嵌套深度。

代价：消息多的时候平铺会更长，而侧栏不能滚动——所以必须配合折叠或分页， 这正是不能只靠嵌套盒子堆内容的原因。

为什么差这么多

四条都是结构层面的，不是配色或间距问题。

一、现状是 9 轮迭代叠出来的，原型是照着 API 清单画的

全局

现状里每个 box、每个图标都有来历。原型是拿实测的 UILayout 接口清单从头排的， 天然会整齐。所以"差很多"里有一部分是新画 vs 旧的，不是方案 vs 现状。

二、现状靠嵌套盒子划分层级

ui.py:963 / 1003 / 1010

cbox.box() → abox.box() → sbox，三层套下来。 Blender 的 box 没有阴影也没有外边距，嵌套再多层，看起来也就是一块更深的底色——层级信息基本丢失。

三、折叠是手搓的，不是原生的

ui.py:983 / 1045

「收起详情」「查看原选项」是 deepseek.toggle_card operator 加一个 RIGHTARROW 图标， 再靠 state.show_card_qa 决定画不画内容。Blender 5 有 layout.panel()， 自带折叠箭头和展开动效，不需要自己维护状态位。

四、手动换行是当前最痛的一处

ui.py:959 / 993

get_wrap_width() 用 region.width 和 ui_scale 反推"能放几个字符"， 再用 _wrap() 切行。但字符宽度是估算的，中英混排也对不齐—— 结果就是截图里那种 茶… 0 轮对话 …续对话)。Blender 的 label() 本身不换行也不省略， 这不是 API 缺陷，是它压根不提供排版能力。

我上一版原型哪里不准确

  • 按钮画成了扁平，你实际用的是 emboss 凸起样式，有明显的高光渐变。
  • 假设文字放得下。原型里「当前会话：中式紫砂茶杯」完整显示，实际侧栏窄一点就被切成「茶…」。
  • 侧栏画得偏宽，控件行高和内边距是估的，比真实偏松，所以显得更"通透"。
  • 没画出双 tab 的割裂感。真实界面里面板头「AI 对话」下面紧跟着一条横向切换条， 再加右侧竖排原生 tab，同一件事有两套导航，原型里我把这条切换条去掉了，所以少了割裂感。
  • 配色可信，度量不可信——色值是实测的，间距不是。
